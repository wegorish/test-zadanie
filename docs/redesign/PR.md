# Редизайн UX «ОфисСклад» по итогам Метрики и аудита

Сайт подстроен под главный сценарий постоянного оптовика: найти по коду или названию из прайса, собрать корзину, заказать.
Новичку сразу видны условия опта.

Внешний вид меняли минимально: структура страниц, фирменный фиолетовый, логотип и адреса страниц те же.
Всё работает на статическом хостинге GitHub Pages. Корзина, вход и поиск работают в браузере (localStorage и JSON-индекс).
Надпись «Заказы не передаются поставщику» осталась.

## Что не сделано или сделано заглушкой

**Ждёт ваших данных или согласования**
- **Тексты** оффера на главной, полосы условий, «Зачем регистрироваться» и шагов доставки — заглушки на согласование.
- **Порог «Мин.цены»** — 30 000 ₽, заглушка `minPriceFrom` в `js/config.js` (открытый вопрос ТЗ).
- **ТК и сроки по регионам** на «Доставке» — метки «[уточнить]» (открытый вопрос ТЗ).
- **Список городов** (16 городов Урала и Сибири) составлен мной по регионам из ТЗ.
- **Реального прайс-листа для проверки заказа списком нет.** `price.csv` — прайс без количества. Количество в списке понимается только в штуках, «2 кор» строкой не распознаётся.
- **Счётчик Метрики** не установлен, как в ТЗ. `METRIKA_ID` пустой. Номер заказа в `purchase` — тестовый номер демо.

**Ограничения статического демо**
- «Забыли пароль?» и «Заказать звонок» — демо: письмо не отправляется, заявка сохраняется только в браузере.
- Два прошлых заказа нового аккаунта — тестовые данные, с пометкой «пример».
- Фильтр по параметрам работает по характеристикам товаров этой копии (200 товаров). Многие значения фильтра относятся к товарам исходного сайта, которых в копии нет, — по ним честно «товаров нет».

**Отличия от буквы ТЗ — сознательные**
- **Окно «нужно авторизоваться» при «В корзину» (P0.1)** заменено гостевой корзиной (P3.1): гость добавляет товар без входа. Окно с кнопками входа осталось для избранного и сравнения.
- **Наличие** берётся со страниц товаров («В наличии: 47», «Ожидается поступление 30.09.2026»), а не из прежнего `products.json`: там были другие числа. 4 товара «ожидаются» и считаются не в наличии.
- **Пункт верхнего меню «Коллекции»** заменён на «Новинки». Число пунктов то же.
- **По «обложки»** находятся все 25 обложек раздела первыми, а за ними 13 дневников и тетрадей «в тв. обл.» — так работает сокращение `обл.` из прайса.

**Доделать можно отдельно**
- На телефоне цена в карточке начинается сразу под фото, но чуть ниже первого экрана (871 px при экране 844 px). Шапка, полоса условий и заголовок в три строки занимают около 550 px. Можно добавить липкую панель «цена + В корзину».
- Скругления и промежутки сделаны для карточек в разделах, выдаче и списках. Слайдеры и «Популярные категории» на главной оставлены в общей сетке темы.
- Автотест поиска — скрипт для Node или JavaScriptCore, а не Playwright: Node в окружении не было. Сценарии 1–3, 5 и 7 проверены в браузере и headless Chrome вручную, без отдельного кода тестов.
- В тестовых данных расходится адрес самовывоза: «Промышленная, 4» на «Доставке» и «Складская, 10» в футере. По ТЗ тестовые данные не трогали.

## Как устроено

- **`tools/build_site.py`** — идемпотентная сборка. Правит все 260 HTML-страниц: шапку, меню, футер, микроразметку, фильтры, габариты, блоки P4, подключение скриптов с `?v=<хеш>` против кэша GitHub Pages. Собирает данные: `products.json`, `search-index.json`, sitemap. `--check` показывает, что пересобирать нечего.
- **`tools/check_links.py`** — краулер ссылок. **`tools/search.test.js`** — автотест поиска.
- **JS-модули в `kanctovar/js/`**:
  - `config.js` — настройки;
  - `metrika.js` — цели и e-commerce;
  - `search.js` — движок поиска без DOM;
  - `search-ui.js` — подсказки и выдача;
  - `catalog.js` — плитка и список, наличие;
  - `filter.js` — фильтр по параметрам;
  - `product.js` — единицы в карточке;
  - `order-list.js` — заказ списком.

  Корзина, вход и заказ — в `demo.js`. Стили — в `demo.css`: дизайн-токены в начале, блоки по этапам P0–P5 ниже.
- Тема Битрикса (`assets/*.css`) не изменялась.

Коммиты по этапам: P0 → P1 (+ правки поиска) → P2 (+ рабочий фильтр) → P3 → P4 → P5 → дизайн → сдача.
